\section*{1. Цель работы}
Освоить передачу данных между процессами через файл, отображённый в общую память, и синхронизацию доступа к общему буферу. Закрепить навыки создания дочерних процессов, обработки ошибок системных вызовов и освобождения системных ресурсов.

\section*{2. Задание}
Родительская программа создаёт два дочерних процесса, представленных отдельной программой. Пользователь вводит имена двух выходных файлов, затем строки произвольной длины. Строки длиной не более 10 байт направляются первому дочернему процессу, более длинные --- второму. Каждый дочерний процесс удаляет гласные из полученных строк и записывает результат в свой файл и стандартный вывод.

Для обмена родителя с каждым дочерним процессом используется отдельный отображаемый в память файл. Передача порций данных и ожидание освобождения буфера согласуются межпроцессными семафорами. Пустая строка завершает ввод.

Ограничение «10 байт» соответствует фактической реализации: программа применяет \texttt{std::string::length()} к UTF-8 строке. Для ASCII байты и символы совпадают; для кириллицы --- нет.

\section*{3. Теоретические сведения}
\subsection*{3.1. Отображаемый в память файл}
В POSIX-системе родитель создаёт файл вызовом \texttt{open()}, задаёт размер через \texttt{ftruncate()} и отображает его в память вызовом \texttt{mmap(..., MAP\_SHARED, ...)}. Дочерний процесс открывает тот же файл и создаёт собственное отображение. Адреса отображений могут различаться, однако записи в общий участок видны обоим процессам. После завершения работы отображение снимается вызовом \texttt{munmap()}, файловый дескриптор закрывается, а файл удаляется владельцем через \texttt{unlink()}.

\subsection*{3.2. Семафоры и протокол обмена}
Один общий буфер передаёт данные в направлении от родителя к ребёнку. В структуре \texttt{SharedBlock} находятся семафоры \texttt{empty} и \texttt{ready}, флаги \texttt{last} и \texttt{finished}, длина \texttt{len} и массив \texttt{data[4096]}. Семафоры создаются через \texttt{sem\_init()} с параметром \texttt{pshared = 1}, чтобы ими могли пользоваться разные процессы.

Начальное значение \texttt{empty = 1} означает свободный буфер, \texttt{ready = 0} --- отсутствие новой порции. Родитель ждёт \texttt{empty}, записывает порцию и вызывает \texttt{sem\_post(ready)}. Ребёнок ждёт \texttt{ready}, читает порцию и вызывает \texttt{sem\_post(empty)}. Для длинной строки обмен повторяется; \texttt{last = 1} помечает последнюю порцию. После конца ввода родитель устанавливает \texttt{finished = 1} и сигнализирует через \texttt{ready}.

Без синхронизации родитель мог бы перезаписать данные раньше чтения ребёнком. Семафоры обеспечивают чередование «запись --- чтение» и не позволяют обеим сторонам одновременно считать буфер доступным для записи.

\subsection*{3.3. Создание и ожидание процессов}
Родитель вызывает \texttt{fork()}, затем дочерняя ветвь --- \texttt{execl()} для запуска отдельной программы \texttt{child}. Родитель сохраняет PID и после окончания передачи вызывает \texttt{waitpid()} для обоих процессов. В ожидании свободного буфера применяется \texttt{sem\_timedwait()} с интервалом 100 мс; при истечении времени родитель проверяет, не завершился ли ребёнок, через \texttt{waitid(..., WNOHANG | WNOWAIT)}. Это позволяет выйти из ожидания, если получатель аварийно завершился.

\subsection*{4.2. Алгоритм родительского процесса}
\begin{enumerate}
\item Прочитать два имени выходных файлов.
\item Создать \texttt{channel1.mmap} и \texttt{channel2.mmap}, в каждом инициализировать общий блок и два семафора.
\item Запустить двух детей; каждому передать имя выходного файла, идентификатор и путь к его каналу.
\item Для каждой непустой строки определить длину через \texttt{std::string::length()}. При длине \texttt{> 10} передать строку второму ребёнку, иначе --- первому.
\item При конце ввода отправить через оба канала признак завершения, дождаться детей с помощью \texttt{waitpid()} и вывести их коды возврата.
\item При уничтожении каналов снять отображения, закрыть файлы, уничтожить семафоры и удалить временные файлы.
\end{enumerate}
\subsection*{4.3. Алгоритм дочернего процесса}
Дочерняя программа открывает свой выходной файл и подключается к соответствующему отображаемому файлу. В цикле она получает полную строку, собирая её из порций при необходимости. После обработки функцией \texttt{remove\_vowels()} результат записывается в файл и выводится в консоль. Признак \texttt{finished} завершает цикл.

Функция \texttt{remove\_vowels()} удаляет английские гласные \texttt{a}, \texttt{e}, \texttt{i}, \texttt{o}, \texttt{u}, \texttt{y} в обоих регистрах. В коде также указан набор русских гласных, однако перебор выполняется по отдельным байтам UTF-8. Поэтому для кириллицы результат может быть некорректным; корректное удаление русских букв требует обработки символов Unicode, а не байтов.

\subsection*{4.4. Передача длинной строки}
Если длина строки превышает 4096 байт, метод \texttt{SharedChannel::write()} делит её на порции по размеру буфера. Ребёнок добавляет порции в одну строку, пока не получит \texttt{last = 1}. Пустая строка не передаётся как данные, потому что в родителе она служит признаком завершения ввода.

\section*{5. Проверка и результаты}
\subsection*{5.1. Сборка}
Проект проверен на доступной машине с macOS: CMake настроил сборку, однако компиляция POSIX-модуля остановилась на вызове \texttt{sem\_timedwait()} --- эта функция в используемом SDK macOS не объявлена. Следовательно, полный запуск двух процессов в этой среде не проводился. Для воспроизведения лабораторной нужен Linux с поддержкой межпроцессных неименованных семафоров.

cmake --build build
cd build

\subsection*{5.3. Обработка отказа дочернего процесса}
При ошибке создания процесса программа сообщает о ней. Если запущенный ребёнок завершится до чтения следующей порции, \texttt{sem\_timedwait()} периодически выходит по тайм-ауту, а \texttt{waitid()} позволяет обнаружить завершение. Родитель прекращает передачу в этот канал и сообщает об ошибке, избегая бесконечного ожидания свободного буфера.

\section*{6. Выводы}
В лабораторной работе реализована однонаправленная передача строк от родителя к двум дочерним процессам через отдельные отображаемые в память файлы. Межпроцессные семафоры согласуют запись и чтение общего буфера; флаги в нём задают границы строк и завершение потока данных. Длинные строки передаются порциями, а тайм-аут ожидания позволяет обнаружить преждевременное завершение получателя.

Анализ исходников подтверждает архитектуру и алгоритм обмена. Полный запуск требует Linux: на доступной macOS сборка останавливается из-за \texttt{sem\_timedwait()}. До сдачи работы следует выполнить контрольные сценарии на Linux, исправить побайтовую обработку кириллицы, если она требуется заданием, и не заявлять поддержку Windows без реализации \texttt{process\_win.cpp}.
